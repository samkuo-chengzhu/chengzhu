Solutions

不是再多一套工具，
而是一套能一起運作的系統。

從顧客接觸、內部作業到管理決策，橙築以企業流程為核心， 選擇合適的技術並負責把它們接起來。 以下每一項底下列的都是實際交付過的功能，不是規格表。

01

企業網站與會員平台

網站的工作不是好看，是把對的人帶進來、把詢問變成可追蹤的資料。 品牌官網、內容管理、會員分級與多語系，讓網站成為可衡量的營運入口， 而不是一年更新一次的型錄。

我們實際做過
  • B2B 企業採購平台前台：商品展示、查價、下單與售後追蹤
  • 會員平台：註冊綁定、分級權益、消費紀錄與活動通知
  • 品牌展示站與商品型錄，含 SEO 結構與社群分享卡片
  • 詢問表單直接收進後台與 LINE 通知，不停在信箱

可以先玩：選物商城 Demo — 完整的瀏覽、購物車與結帳流程

內容架構 / UIUX / SEO / CMS / 會員分級 / Firebase Auth

02

ERP 與流程中台

把採購、庫存、工單、對帳與報表收進同一套可追蹤的工作流程。 重點不是功能多，是每一個狀態都有人負責、有時間戳、 而且下一步該做什麼是系統說了算，不靠記憶與口頭交代。

我們實際做過
  • 工單全流程：已成立 → 待料 → 組裝中 → 可取桿 → 已交付，完成動作才能前進
  • 掃碼收貨、出貨與盤點，每一筆都留異動帳與條碼紀錄
  • 1,858 筆料件的即時庫存，含雙價、廠商與門市有無庫存標記
  • 缺料自動進待訂貨清單，通知訂貨與到貨都記錄人與時間
  • 指派技師與工時區段，沒指派不能進入下一階段
  • 電商與門市共用同一份商品與庫存資料，不用兩邊各記一次

進銷存 / 掃碼盤點 / 工單看板 / 多倉 / PostgreSQL / Firestore

03

CRM 與會員經營

從第一次詢問到成交後服務，完整累積每一位客戶的互動、消費與偏好。 資料不是為了做報表而存在，是為了讓下一次接觸的人 知道這位客戶上次談到哪裡。

我們實際做過
  • 對話式會員綁定：在 LINE 裡完成，不用另外下載或註冊
  • 會員卡、消費紀錄與年度消費自動累計
  • 等級與標籤分群，供後續分眾推播使用
  • 客戶偏好與量身資料留存，回訪時直接調得出來
  • 跨據點共用同一份會員資料與權益

可以先玩：教練預約 Demo — 含堂數與會員紀錄管理

名單 / 標籤 / 會員卡 / 消費紀錄 / 分眾推播 / Pipeline

04

POS 與門市營運

前台掃碼成交之後，庫存、會員、業績與帳務同一秒更新。 門市不該是「白天做生意、晚上再對一次帳」， 那些重複輸入本來就該由系統處理掉。

我們實際做過
  • 門市平板 POS 刷條碼結帳，庫存即時扣減
  • 營收自動結算到日、到月，不用手動彙整
  • 設計師與門市的業績拆帳自動計算，後台直接看得到帳
  • 線下付款流程：匯款與店內付款，宅配或店取
  • 電商與門市庫存同一份，避免超賣

可以先玩：髮廊 Demo — 營收拆帳與儀表板

條碼結帳 / 即時庫存 / 拆帳 / 對帳 / 跨通路同步

05

LINE Bot 服務流程

預約、通知、查價、客服與售後，全部發生在客戶本來就每天在用的介面裡。 不用說服任何人下載新的 App，也不用教長輩怎麼登入—— 這是導入成本最低的一條路，也是橙築累積最深的一塊。

我們實際做過
  • Rich Menu 全對話式操作，六格功能不需離開 LINE
  • LIFF 頁面：預約、選課、報名、商品瀏覽與結帳
  • 自然語言查價與下單，業務在群組講一句話就能報價
  • 大型群組一鍵報名、候補自動遞補與自動分組
  • 排程推播：明日行程、到期提醒、庫存警示、內部通知群
  • 拍照上傳自動歸檔，以及發票影像辨識與防重複登記

五個 Demo 全部都是 LINE 場景：查看總覽

官方帳號 / LIFF / Rich Menu / Flex Message / 推播 / Webhook

06

資料與營運儀表板

把跨系統的資料收攏成看得懂的數字，以及該處理的任務。 我們的做法是先讓資料乾淨且只進一次， 再談自動化——順序反過來做出來的都是漂亮但沒人打開的報表。

我們實際做過
  • 營運總覽儀表板：營收、工單進度、會員活躍與庫存狀態
  • 週報與月報自動產出並寄送，取代人工彙整
  • 教練與門市月結報表，含拆帳與場地收入
  • 影像辨識自動讀取單據資料，減少人工key單
  • 每日自動抓取外部價格資料進資料倉儲，供比價與定價參考
  • 階梯定價引擎：依客戶分級自動套用不同報價

可以先玩：智能查價 Demo — 自然語言查價與階梯定價

儀表板 / 自動報表 / 異常預警 / OCR / 資料倉儲 / 定價引擎
